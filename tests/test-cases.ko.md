# 테스트 케이스 목록 (한글 정리)

이 문서는 `shopping-mall-harness` 쇼핑몰 사이트가 의도한 대로 동작하는지 확인하는
테스트 케이스를 사람이 읽을 수 있는 말로 정리한 것입니다. 실제로 이 케이스들을
자동으로 실행하는 코드는 `tests/e2e/*.spec.js`(Playwright)에 있으며, 이 문서는 그
코드의 요약본입니다. 함수/테스트 이름은 참고용으로만 괄호에 적어둡니다.

각 항목은 PRD(`_workspace/01_planner_prd.md`)의 요구사항 번호와 매핑되어 있어서,
어떤 요구사항이 테스트로 커버되는지 추적할 수 있습니다. 사이클별로 섹션을 나누고,
기존 항목은 지우지 않고 이어서 추가합니다.

## 3차 사이클 — 장바구니 전체 비우기 + 수량 할인

> 자동화 파일: `tests/e2e/cart.spec.js`

### 전체 비우기

(`cart.spec.js` › `장바구니 전체 비우기 (PRD 11.1~11.5, 13.2)`. 11.2는 클릭 후 나간 요청을
전부 기록해 `DELETE /api/cart` **한 건뿐**임을 확인하고, 11.4는 다이얼로그 리스너를 미리 걸어
한 번도 발화하지 않는 것을 확인한다. 11.5는 "DOM에 존재"와 "화면에 안 보임"을 각각 단언한다)

| PRD | 시나리오 |
|---|---|
| 11.1 | 장바구니 화면에 "전체 비우기" 버튼이 있다 |
| 11.2 | 버튼을 누르면 한 번의 요청으로 장바구니 전체가 비워진다 (항목을 하나씩 지우는 방식이 아니다) |
| 11.3 | 이미 비어있는 장바구니에서 비우기를 시도해도 에러가 나지 않는다 |
| 11.4 | 비우기 버튼을 눌러도 "정말 비우시겠습니까?" 같은 확인창이 뜨지 않고 바로 처리된다 |
| 11.5 | 장바구니가 비어있을 때는 비우기 버튼 자체가 화면에서 숨겨진다 |

### 수량 기반 자동 할인

(`cart.spec.js` › `수량 기반 자동 할인 (PRD 12.1~12.13, 14.2~14.5)`. 12.4는 할인 요소를
`toHaveCount(0)`으로(숨김이 아니라 부재), 함정 케이스는 9개일 때와 10개일 때의 줄 합계 문구가
**실제로 같다는 것까지 확인한 뒤** 할인 표시 요소의 존재 여부로 통과 판정을 한다)

| PRD | 시나리오 |
|---|---|
| 12.1 | 한 상품을 장바구니에 **9개** 담으면, 할인이 적용되지 않고 정가로만 표시된다 |
| 12.2 | 같은 상품을 **10개** 담으면, 그 줄 전체에 10% 할인이 자동으로 적용된다 |
| 12.3 | 할인이 적용된 줄에는 원래 가격(취소선) + 할인된 가격 + "10개 이상 담으면 10% 할인 적용" 안내 문구가 표시된다 |
| 12.4 | 할인이 적용되지 않은 줄에는 할인 관련 표시(할인가, 안내 문구)가 아예 나타나지 않는다 (흐리게 숨기는 게 아니라 화면에 존재하지 않음) |
| 12.5 | 할인 여부는 상품 줄마다 각자 독립적으로 판단된다 — 한 상품이 6개, 다른 상품이 5개면 합쳐서 11개가 되어도 어느 쪽도 할인되지 않는다 |
| 12.6 | 장바구니 전체 합계는 할인이 반영된 금액의 합이다 |
| **함정 케이스** | 9개일 때와 10개일 때 최종 줄 합계 숫자가 우연히 똑같아 보일 수 있다 (정가 × 9 = 할인가 × 10인 경우). 이런 경우에도 "금액이 맞다"가 아니라 "할인 표시(취소선·안내 문구)가 실제로 뜨는지"를 기준으로 통과 여부를 판단해야 한다 |

## 자동화 현황

**위 케이스는 전부 자동화되어 있습니다.** (2026-08-09 작성)

| 파일 | 담당 화면 | 테스트 수 |
|---|---|---|
| `tests/e2e/landing.spec.js` | 상품 목록(홈) — 1차 사이클 전체 | 10 |
| `tests/e2e/product-detail.spec.js` | 상품 상세 — 2차 사이클 | 11 |

실행 방법은 `npx playwright test` 한 줄입니다. 설정은 프로젝트 루트의 `playwright.config.js`에
있고, 3000 포트에 서버가 이미 떠 있으면 그 서버를 그대로 재사용합니다(`reuseExistingServer`).
**최근 실행 결과: 45개 전부 통과 (실패 0건).**

### 브라우저 창을 파일당 하나만 씁니다 (2026-08-09 변경)

테스트 개수와 내용은 그대로 45개입니다. 달라진 것은 **창이 몇 번 열리는가** 하나입니다.

- 예전에는 테스트 하나마다 새 브라우저 창이 열리고 닫혔습니다. `--headed`로 직접 지켜보면
  창이 45번 깜빡여서 무엇을 보고 있는지 알기 어려웠습니다.
- 이제는 **spec 파일 하나가 창 하나를 끝까지 같이 씁니다.** 파일이 3개이므로 창도 3개입니다.
  (`npx playwright test --headed --workers=1`로 확인한 실제 결과입니다.)
- 예외가 하나 있습니다. "서로 다른 브라우저는 장바구니가 서로 독립적이다"(8.5)와
  "처음 방문한 브라우저에 식별 정보가 새로 발급된다"(8.2/8.4)는 요구사항 자체가 창 여러 개를
  전제로 합니다. 이 두 케이스만 자기 창을 따로 열어 검증하고, 끝나면 바로 닫습니다.
  그래서 한 번 실행에 만들어지는 창은 총 6개입니다(공유 3 + 예외 3).

창을 같이 쓰면 장바구니(쿠키)도 같이 쓰게 되어, 앞 테스트가 담아둔 상품이 다음 테스트에
그대로 남습니다. 그래서 **각 테스트는 시작할 때 서버 장바구니를 비우고 시작합니다.**
"앞 테스트가 뭘 남겼든 상관없이 같은 결과가 나온다"는 성질은 그대로 유지하되, 그 방법만
"매번 새 창"에서 "매번 빈 장바구니"로 바꾼 것입니다. 단언을 느슨하게 만든 곳은 없습니다.

읽을 때 참고할 점 몇 가지입니다.

- 각 테스트는 빈 장바구니에서 시작하므로 장바구니가 서로 섞이지 않습니다. 화면을 가로채는
  설정(예: "이미지가 전부 실패하는 상황")도 테스트가 끝나면 원래대로 되돌립니다.
- 파일끼리는 여전히 동시에 실행되고, 서로 다른 창이라 장바구니도 서로 다릅니다.
  다만 한 파일 안에서는 적어놓은 순서대로 실행됩니다(창을 같이 쓰기 위한 조건입니다).
- 화면에 보이는 금액은 테스트가 직접 계산하지 않고, 매번 서버에 장바구니를 따로 물어봐서
  그 값과 글자 단위로 비교합니다 (7.6 규칙을 테스트도 그대로 지킵니다).
- "요청이 나가지 않아야 한다"는 케이스(6.9, 7.4, 11.2, 7.8)는 화면 모양이 아니라
  **실제로 오간 요청 개수**로 확인합니다.
- 요소가 "화면에 안 보이는 것"(비우기 버튼, 합계 영역, 수량 배지)과 "아예 없는 것"(할인 표시)은
  서로 다른 방식으로 확인합니다. 이 둘을 섞으면 할인 경계 버그를 놓칩니다.
