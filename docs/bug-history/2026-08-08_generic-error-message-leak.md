# 공용 에러 핸들러가 엉뚱한 문구를 내보냄 (M5)

## 한 줄 요약
`/api/*` 아무 경로에서나 예상 못 한 예외가 나면, 실제로 어느 API에서 터졌는지와
무관하게 항상 "상품 목록을 불러오지 못했습니다."라는 **고정 문구**가 나간다.
장바구니 화면에서 에러가 나도 화면에 "상품 목록을..."이라는 문구가 뜬다.

## 왜 생겼나 (근본 원인)
가장 먼저 만든 상품 목록(`GET /api/products`) 기능을 위해 짠 공용 5xx 에러 핸들러를,
나중에 장바구니 API들을 추가할 때 **그대로 재사용**했다. 만들 당시엔 "상품 목록"
API 하나뿐이었으니 문구가 맞았지만, API 종류가 늘어나면서 문구가 안 맞게 됐다.

## 재현 조건
- `/api/*` 아래 어떤 엔드포인트든, 예상 못 한 서버 예외(500)가 발생하는 모든 경우
- 특히 상품 목록이 아닌 다른 기능(장바구니, 상세 등)에서 발생할 때 문구가 어긋남

## 왜 다시 터질 수 있는가 (다음 기능에서 주의할 점)
**"기존 공용 에러 핸들러를 그대로 재사용해서 새 API를 추가하는 패턴"에서 항상 재발
가능하다.** 특히:
- 결제(체크아웃) API를 추가할 때, 지금 있는 공용 500 핸들러를 그대로 물려받으면
  결제 실패 화면에도 "상품 목록을 불러오지 못했습니다"가 뜰 것이다
- 앞으로 기능이 늘어날 때마다 "이 공용 핸들러 문구가 지금 추가하는 기능에도
  맞는 문구인가?"를 매번 확인해야 한다

## 수정 방향 (아직 미적용)
1. 에러 핸들러에서 요청 경로를 보고 문구를 분기한다 (예: `/api/cart*` →
   "장바구니 요청을 처리하지 못했습니다.")
2. 또는 애초에 기능명이 안 들어간 중립적인 문구("요청을 처리하지 못했습니다.")로
   바꾼다 — 이 방법이 새 기능 추가할 때마다 안 건드려도 돼서 더 안전함

## 관련 파일 (2차 사이클 시점 기준)
- `server.js` — 공용 에러 핸들러 (5xx 응답 생성 지점)
